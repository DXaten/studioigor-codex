# Visual references and asset provenance

Show 2–4 directions for composition, palette, lighting, texture, typography, and camera. Use actual game screens or other visual references when possible. A reference board is for communicating taste; it is not permission to copy protected art into the game.

The original project's `scripts/refs.py` can collect reference images and `scripts/board.py` can show a local selection board. Check `--help` for supported sources and options. If a browser or image tool is better suited to the session, use it. Generated concepts may supplement references, labeled as generated.

After the user chooses a direction, record a small palette, form rules, interface rules, and 2–3 recognizable motifs in `ART_BIBLE.md`. Build a real look-development scene from those rules before producing many assets.

Record every third-party game asset in `ASSETS.md`: source URL, creator, license, required credit, whether modification is permitted, and where it appears. Use assets only under terms that permit the planned game release. Keep credits current as assets are replaced.
